# Fabrik3D — Release notes, Roadmap Revision 4 (S65–S71)

Release date: 2026-10-03. Status: **finalized by S71** after the Revision 4 validation record and the
measured Revision 3 → Revision 4 GPU comparison were produced
([`S71-revision4-validation-demo.md`](../roadmap/sprints/S71-revision4-validation-demo.md)). The
architecture and asset/layout facts below remain renderer-independent; the performance statement
links the measured comparison and claims no blanket improvement.

Release candidate: **v1.2.0** (recommended; see
[`RELEASE_PREPARATION_REVISION_4.md`](../operations/RELEASE_PREPARATION_REVISION_4.md) for the rationale
and the non-moving `v1.1.0` tag). Revision 4 builds on the immutable 1.0 baseline, the completed
Roadmap Revision 2 (S51–S57, tagged `v1.1.0`) and the completed Roadmap Revision 3 (S58–S64). It adds
no protocol, database, product or safety capability.

## Highlights

- **Scenario-specific industrial 3D assets (S65).** The five flagship scenario cells prefer 26
  generated, license-safe, moderate-budget GLB packages over the S58 procedural visuals, which remain
  the deterministic fallback. Every package is texture-free, triangle-budgeted, hash-verified and
  regenerated byte-deterministically by `npm run assets:generate`.
- **Real robot motion in scenario cells (S66).** A thin `ScenarioRobotMotionAdapter` maps authoritative
  scenario state to declared joint-space waypoints and drives the existing `RobotController` /
  `RobotVisualBinding` / `MotionSafetyEngine`. There is still exactly one robot authority; simulated
  safety conditions inhibit motion and it is not a certified safety function.
- **Deeper deterministic process flows (S67).** The four material-flow cells are expressed as ordered
  process stages with declared simulation-time durations, fault points and recovery points, with
  continuous, paced and guided/Step Mode execution.
- **PBR materials and factory environment (S68).** A shared, texture-free PBR material vocabulary and
  a coherent industrial ground layer replace per-builder material literals. The appearance stays
  render-only and never becomes collision, runtime, scenario or telemetry truth.
- **Measured composition and cameras (S69).** Derived `overview` / `operator` / `workcell` cameras and
  a composition test enforce overlap, bounds, reach, clearance and frustum containment for all five
  flagship cells.

## Flagship demonstration

The documented authoritative workflow is unchanged and is validated in S71:

```text
HMI → New Job → scenario/cell/pallet → Create → Start → server targeted dispatch →
simulator ACK → automatic 3D execution → robot/CNC/conveyor → live HMI →
fault/recovery → Job 100 % → Completed → historian/time travel
```

- Runbook: [FLAGSHIP_DEMO.md](../operations/FLAGSHIP_DEMO.md)
- Captures and media inventory: [`artifacts/demo/flagship/`](../../artifacts/demo/flagship/README.md)
- S71 execution capture: 21 stage stills (five declared stages each for palletizing, vision sorting,
  assembly/inspection and safety training, plus CNC running) under
  [`artifacts/demo/flagship/execution/`](../../artifacts/demo/flagship/execution/), reproduced by
  `demo-11-execution-stages.spec.ts`. They show real declared S67 process stages, not idle cells.
- The CNC HMI → server → simulator ACK → automatic 3D execution → completion → historian/time-travel
  workflow is proven by `FlagshipWorkflowIntegrationTests`, `FlagshipDemoHistorianTests`,
  `flagship-demo.spec.ts` and the no-simulator-local-Start test.

## Compatibility and migration

- **No migration is required.** Revision 4 changes generated visual assets, scenario process timing
  metadata and layout/camera derivation only. Scenario ids, expected events, success criteria, cell
  composition, REST/SignalR contracts, persisted document schemas and connector mappings are
  unchanged. Older scenarios remain valid; the added `ScenarioActivity` fields
  (`durationSeconds`, `stageId`, `faultPoint`, `recoveryPoint`) are optional and additive, and a
  scenario without them falls back to the documented default duration.
- Procedural fallback remains supported: a missing, corrupt or absent GLB degrades to the procedural
  visual with a diagnostic and never blocks scenario logic.
- Existing documentation, runbooks and the 1.0 reference sample remain valid.

## Validation

The full automated, visual, hardware-benchmark, fixture and manual gate results are recorded in
[VALIDATION_REVISION_4.md](../operations/VALIDATION_REVISION_4.md), together with the measured
Revision 3 → Revision 4 comparison (triangles, draw calls, load time, FPS and frame p50/p95/p99 on
the documented reference machine). The comparison is mixed: fidelity (triangles and draw calls)
increased by design with the S65 scenario assets, S66 robot motion and S68 materials, while FPS stayed
within a few percent on five of six profiles; **no blanket improvement is claimed**. The preceding
record is [VALIDATION_REVISION_3.md](../operations/VALIDATION_REVISION_3.md); the recorded hardware
benchmark is [PERFORMANCE.md](../operations/PERFORMANCE.md).

## Known boundaries

- The platform is simulated throughout; no certified safety function, OEM emulator or real-PLC
  integration is claimed. Real PLC/PLCSIM remains explicitly deferred.
- The generated GLB assets are original generic geometry under the Fabrik3D educational license; no
  OEM model, scan or texture is included.
- Visual meshes never become the FK/IK, collision, safety or telemetry authority.
- See [LIMITATIONS.md](../operations/LIMITATIONS.md) for the consolidated non-claims.
